# #188 Paper audit, 2026-10-20

Read-only audit of the Paper look against the code on main (`1a6f44d`). Nothing in `src/` changed. Inputs: CLAUDE.md, issue #188 and its three comments, `docs/design-system.md`, `docs/superpowers/ledgers/2026-09-06-188-paper-slice-1-progress.md`, `src/app/globals.css`.

Rule set judged against (from the issue, the design system and the slice 1 ledger):

1. Colours come from the `globals.css` tokens. No dark literals, no Tailwind palette classes.
2. No shadows. A 1px border is the only separator.
3. Ink borders on controls, hairline (`--border`) on resting dividers.
4. Labels are mono uppercase.
5. Rose is on the wordmark and the Generate button only.
6. Light only. No `dark:` or `prefers-color-scheme`.

Prod and prntd.org are unreachable from a cloud session, so this is a code judgement. Nothing was rendered.

Greps over the 226 non-test files under `src/` (`*.ts`, `*.tsx`, `*.css`, `*.svg`), plus a throwaway script (not committed) that reads every class string for a `border` or `divide` utility with no colour utility beside it.

## Things the code cannot show

1. **Stripe's embedded and hosted forms.** No `appearance` or branding option is set anywhere in the repo, so their colours, font and button come from the Stripe account's branding or Stripe's default. This is the one surface a buyer sees that this repo does not style.
2. **Contrast.** The doc's ratios were computed on 2026-09-06 and were not recomputed. No token has changed since, so I did not.
3. **Emails in a real client.** The HTML is table and inline style, with a system sans stack and no mono labels. I read it; I did not render it in Gmail or Apple Mail.
4. **Satori OG rasters** cannot render under vitest (CLAUDE.md), so the OG verdict is from the markup.
5. **`<meta name="theme-color">`.** Only the PWA manifest sets it (`manifest.ts:21`). A phone browser's address bar gets no Paper tint. Not a departure from the rules above; stated so it is known.
