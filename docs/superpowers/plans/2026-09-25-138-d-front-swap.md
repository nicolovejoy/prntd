## What ships

On the image detail page, once a back design is picked, the buyer can swap
the two sides: the picked image goes on the front and the page's own image
goes on the back. There is still no general front picker on this page.

## Rules the slice holds

1. **Swap only.** A front other than the page image is valid only as a swap:
   the page image must then be the back. Enforced server-side at both
   checkout choke points (`buyPublishedDesign`, `addToCart`'s `frontImageId`
   entry), not just by the UI. The page image is what `order.designId`,
   `order.storeProductId` and the page URL name, so it must stay on the
   shirt.
2. **Same guard as the back.** The override clears
   `assertUsablePlacementImage` (→ `canUseAsPlacementSource`): the buyer's
   own image, or published and not hidden. A cross-owner private or hidden
   id throws before any order or cart row is written.
3. **Price is unchanged by a swap.** `hasBack` is true before and after;
   the server re-derives the price from its own view of the placements.
4. **The Stripe line thumbnail follows the pinned front.** The cancel URL
   keeps pointing at the page the buyer came from (judgment call, ledger).
5. **The pins survive** into `cart_item.placements` and
   `order_item.placements` exactly as sent.

## Tasks

### Task 1 — server: swap-only front override at the checkout choke points

Files: `src/lib/placement-pins.ts`, `src/app/d/actions.ts`
(`buyPublishedDesign`), `src/app/cart/actions.ts` (`addToCart`), tests.

- `placement-pins.ts` gains pure `resolveBuyPageFront({ pageImageId, front,
  back })`: returns the front id to pin. `front` absent or equal to the page
  image → the page image. Any other `front` → returned only when `back ===
  pageImageId`; otherwise throws.
- `buyPublishedDesign` takes optional `frontImageId`. Resolved after the back
  (so a flag-off back that gets dropped also refuses the override). A
  non-page front is guarded with `assertUsablePlacementImage(…, "front")`.
  `placements.front` = the resolved front. `checkoutImageUrl` = the resolved
  front's URL. Cancel URL unchanged.
- `addToCart`: on the `frontImageId` entry, `front` is now honoured as the
  swap override under the same rule and guard (was: ignored). The
  `designId` entry is unchanged.

Acceptance:
- Swap order: `order_item.placements = { front: <picked>, back: <page> }`,
  `itemPrice` equal to the unswapped two-sided price, Stripe line image = the
  picked image's URL, `order.designId` and `order.storeProductId` unchanged
  from the unswapped order.
- Cross-owner private and admin-hidden override ids throw
  `Front image is not available`; no order / order_item / cart row.
- An override without the page image on the back throws; no rows.
- Flag off: override refused (the back is dropped, so it is not a swap).
- `frontImageId` equal to the page image behaves exactly as today.
- Cart: swap line pinned `{ front: <picked>, back: <page> }`, cart
  thumbnail = picked image, pins survive `checkoutCart` into `order_item`.

Tests: unit (`src/lib/__tests__/placement-pins.test.ts`), real-DB
(`src/app/d/__tests__/buy-published-design-swap.integration.test.ts`,
`src/app/cart/__tests__/add-to-cart-swap.integration.test.ts`).

### Task 2 — mockup: the hero can render the swapped front

Files: `src/app/d/actions.ts` (`getListingMockup`), its integration test.

- `getListingMockup` takes optional `frontImageId`. When it differs from the
  page image: requires `MULTI_PLACEMENT_ENABLED` (a swap needs a back, same
  gate as `getListingBackMockup`) and `assertUsablePlacementImage(…,
  "front")` with the viewer (`""` when signed out), then renders with
  `sourceImageId = frontImageId`. Absent or equal: byte-identical call.

Acceptance: override renders with the override as `sourceImageId`; private
and hidden cross-owner overrides throw with no render; flag off throws; the
page's own visibility gate still runs first.

Tests: extend `src/app/d/__tests__/get-listing-mockup.integration.test.ts`.

### Task 3 — UI: Front row + Swap in BuyPanel; the hero follows

Files: `src/app/d/[imageId]/buy-panel.tsx`, `buy-hero.tsx`,
`src/lib/placement-pins.ts` (pure `buyPagePlacements`), tests.

- `buyPagePlacements({ page, added, swapped })` → `{ front, back }` picks.
- BuyPanel: new optional `imageUrl` prop (the page image, for the Front row
  thumbnail and the report), `swapped` state. Section label becomes
  "Front & back". With a back picked: Front row (thumb, no controls), Back
  row (thumb; Change only while not swapped; × on whichever row holds the
  pick — amended in review fix round 1), and "⇅ Swap front and
  back" (hidden when the pick is the page image itself). Picking a back or
  removing it resets `swapped`. `onBackChange` reports the effective back;
  new `onFrontChange` reports the effective front. Buy sends `frontImageId`
  and cart sends `front` only when the front differs from the page image.
- BuyHero: holds the reported front; the front instant layer, the front
  mockup source (`frontImageId` only when it differs) and the alt text
  follow it. The back tile follows the effective back (the page image after
  a swap).

Acceptance: Swap absent with no back; present with a back; exchanges the
rows and the hero sides; price unchanged; Change hidden while swapped;
swap back restores them; buy/cart payloads carry the override only while
swapped; the front mockup is re-fetched for the new front and the back
for the page image, front first.

Tests: `buy-panel.test.tsx`, `buy-hero.test.tsx`, placement-pins unit.
