## Rules for every controller

You are the SDD controller for one slice. You own one branch in one worktree.

**Process.**
1. Read `CLAUDE.md` (conventions + the Known Issues entry for your area), the
   issue, and any plan doc named for your slice. Read the relevant guide in
   `node_modules/next/dist/docs/` before writing Next.js code (AGENTS.md).
2. Write your plan to `docs/superpowers/plans/2026-09-25-<slug>.md`: tasks
   with acceptance criteria and the tests each adds. Commit it.
3. Per task: dispatch an implementer (model `sonnet`), then a fresh task
   reviewer (`sonnet`), then fix rounds (`sonnet`) with a scoped re-review
   (`haiku`) until clean.
4. After the last task: one fresh whole-branch review (model `opus`) over
   `git diff origin/main...HEAD` **and the files around it**. That pass is the
   one that historically finds the real defects (stale docblocks three lines
   from a change, invariants other modules rely on). Fix, re-review.
5. Gate (all must pass, run them yourself; never trust an implementer's
   report that tests passed):
   - `npm run lint` (0 errors)
   - `npm run typecheck`
   - `npx vitest run`
   - `npm run build` with the CI dummy env (block below)
   - `npm run db:generate` prints "No schema changes" (unless your slice
     carries a migration)
6. Keep a ledger at `docs/superpowers/ledgers/2026-09-25-<slug>-progress.md`
   with every ruling and review finding. Commit it before you finish.
7. Push your branch (`git push -u origin <branch>`; retry on network errors
   with 2s/4s/8s/16s backoff). Do NOT open a PR; the main session does.

**Reviewer prompts.** Never pre-judge: do not tell a reviewer what not to flag.
Give it the plan, the diff range, and the acceptance criteria.

**Never.**
- Edit `CLAUDE.md` (the main session owns it; it conflicts with every branch).
- Add a migration, unless your slice is D.
- Push to any branch but your own. Merge into main. Force-push.
- Skip, disable or weaken a test to get green.
- Add scope. If the plan meets a real product question, pick the option
  closest to the issue's recommendation, record it in the ledger as a
  judgment call, and flag it in your summary.

**Environment facts.**
- The cloud session cannot reach prntd.org or `*.vercel.app`; no prod or
  preview DB; no vendor API keys. CI's `e2e` job runs Playwright on an
  ephemeral Turso branch, so e2e is checked there.
- Worktree `node_modules` is a hardlink copy (`cp -al`) of the main
  checkout's. Don't `npm install` new packages unless your slice needs them
  (C does); if you do, `rm -rf node_modules && npm ci` first so the hardlinks
  are not mutated.
- Chromium is at `/opt/pw-browsers`; `next dev` + Playwright against a local
  `file:` libSQL DB (built with `npm run db:migrate`, which the preflight
  allows for `file:` URLs, or `drizzle-kit migrate`) works for local repros.
