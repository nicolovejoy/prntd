## Rulings made in this plan (Claude's; Nico can reverse each, cost noted)

- **R1. The seed URL carries its own ids and is never stripped.** The seed's address is `/studio?prompt=<text>&lane=<uuid>&seed=<uuid>`. `lane` is the new conversation's id and `seed` is its client job id. The Studio fires one `generateDesign(lane, prompt, { jobId: seed })` on mount, then marks `studio-seed:<seed>` in `sessionStorage` so a remount or reload in that tab does not fire again. If storage is unavailable, or the URL is opened in another tab, the server's replay check returns the original job and nothing is generated twice. Cost if wrong: while the visitor stays on the bench, the address bar keeps the prompt. Removing it later needs a #311-safe write.
- **R2. `/design` with no `id` redirects on the server when there is already a session.** That covers real users and returning guests, so they skip the client hop. Only a sessionless visitor gets the thin client page. Cost if wrong: none. Either way the visitor ends on the same `/studio` URL.
- **R3. Missing or malformed seed ids are filled in by `/studio` itself.** If `prompt` is present but `lane` or `seed` is missing or not a UUID, the Studio page redirects on the server to the same seed with fresh ids. That covers old links, a hand-typed `/studio?prompt=` and a sign-in bounce. Cost if wrong: one extra redirect on such links.
- **R4. A focus wins over a seed.** On `/studio?conversation=&image=` the seed params are ignored, with no fire and no redirect. Cost if wrong: a hand-built URL carrying both shows the stage and drops the idea.
- **R5. A seed that arrives at the in-flight cap is not fired.** Its text goes into the composer for the visitor to send, and the existing cap notice explains why. Cost if wrong: the visitor taps Generate once more.
- **R6. `/studio` gets `export const maxDuration = 300`, the same as `/design`.** The landing visitor's first generation now runs from the Studio, so its `after()` continuation gets the Studio's budget. Every Studio Generate already runs there today with the platform default. This only fixes the ceiling at the value `/design` has. Cost if wrong: none.
- **R7. `design-client.tsx`'s own seed effect becomes unreachable** (that component now renders only for `?id=`, and the effect returns early when `id` is present). It is left in place and deleted with the file in 2c.

### Task 1: `src/lib/studio-seed.ts` (pure helpers)

- [ ] Write failing tests in `src/lib/__tests__/studio-seed.test.ts`, then implement:
  - `export type StudioSeed = { prompt: string; designId: string; jobId: string }`.
  - `seedHref(prompt: string | null | undefined, ids?: { designId: string; jobId: string }): string`: trims the prompt. Empty or missing returns `BENCH_HREF` (`/studio`). Otherwise it returns `/studio?prompt=<encoded trimmed>&lane=<designId>&seed=<jobId>`, minting each missing id with `crypto.randomUUID()`. Build it with `URLSearchParams`.

It returns `{ kind: "complete", seed }` when `lane` and `seed` are each present exactly once and pass `isUuid` (`src/lib/uuid.ts`). Otherwise it returns `{ kind: "incomplete", prompt }`. The prompt in the result is trimmed.
  - `seedFiredKey(jobId: string): string` returns `studio-seed:<jobId>`.
  - Tests:
    - a round trip from `seedHref` through `parseSeed`, with a prompt holding `&`, `?`, `#`, spaces and non-ASCII text;
    - a blank prompt returns `/studio`;
    - each malformed case (missing lane, non-UUID seed, duplicate params) returns `incomplete`;
    - `seedHref` never emits `conversation` or `image`.
