1. **#249 goes first, and the brief does not rank it.** Every merge to main
   forces a re-merge and re-gate of #249, and batch 2 showed that guard
   tests from other PRs break it with no textual conflict. Batch 3 adds
   five to seven merges. Also, #139's migration would be generated as
   `0014` against main's journal and collide with #249's. Running the #249
   runbook before batch 3 builds removes both problems. If Nico would
   rather not, wave 1 can still start under the fence in "Parallelism", and
   #139's migration waits.
2. **#135 is first in order, but the first step is Nico's, not a build.**
   Switching slice 2 on is env work plus a phone test. Slice 3 cannot be
   planned in detail until that test answers whether
   `checkout.sessions.retrieve` returns `client_secret`. So #135 does not
   occupy a builder at the start of the batch.
3. **"Most direct path to more sales" is not established.** Hosted checkout
   works today, and nothing measures the funnel, so there is no evidence
   either way. The reasons to continue are that Nico asked for it and that
   slice 2 is already built. Slice 3 is also the riskiest slice in this
   batch: it moves the main funnel's payment step and rewrites the nightly
   Stripe spec in the same PR.
4. **One mock round for rose, focused stage and icon mark: yes for the
   looking, no for the building.** Rose has to be picked before icon assets
   are cut, because the assets hardcode the hex. The focused stage is a
   different size of work: it decides what happens to `design-client.tsx`
   and the `/design` route. This plan puts its mock and ruling in batch 3
   and its build in batch 4, with its own plan.
5. **#14 is not only data work.** See fact 6. It also needs a ruling on
   how a long swatch list lays out at 390px: 25 swatches is already about
   four rows of seven. The order "#14 before #139" stands.
6. **#139 starts with a read-only spike, not a migration.** The issue
   itself says "not urgent", and nobody has yet checked that a computed
   luminance number agrees with Nico's eye. A spike over the published
   images costs no schema change. The column, backfill and UI follow only
   if the ranking looks right. The issue also frames one direction only
   (colour picked, rank designs). The buy flow more often runs the other
   way (design fixed, which colours suit it), and the same signal serves
   both.
7. **#253 rides along, and builds first.** It is the smallest slice, it is
   the only candidate that closes an open cost hole, and guests can reach
   it today.
8. **Batch size should follow Nico's review and smoke time.** Eight smokes
   are owed already. This plan proposes five build PRs plus one spike, and
   asks for a ruling on the owed smokes (decision 2).

   `docs/superpowers/ledgers/` before removing a worktree.
