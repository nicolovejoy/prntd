# Lightbox on the image detail page and the checkout page (#285)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** tapping the preview image on the image detail page (the artwork before the panel is open, the mockup after) or on a checkout line opens a full-window viewer. One tap or Escape closes it and the page is as it was.

**Architecture:** one new client component, `FullscreenViewer` (`src/components/fullscreen-viewer.tsx`), owns the dialog mechanics: portal to `document.body`, role dialog, Escape, focus trap, focus return, body scroll lock, tap to close, and an optional Front/Back switch. It renders whatever its caller passes as children. The three mount points supply their own content: `SideMockup` for the expanded hero (so the instant layer, the crossfade and the error overlay with Retry are not rewritten), the artwork on its pinned backdrop for the collapsed hero, and the cached mockup or artwork for a checkout line. The viewer's open state is local React state at each mount point. It never touches the URL, `BuyPanel`'s state or the Stripe form.

**Branch:** `claude/285-lightbox`. One PR. No schema change, no server action change, no new dependency.

**Tech Stack:** Next.js 16 App Router (client components only here), React 19, Tailwind v4, Vitest + Testing Library (jsdom), Playwright.

**Spec:** GitHub issue #285 (https://github.com/nicolovejoy/prntd/issues/285) and its comment with Nico's two rulings, 2026-10-05:

1. With a front and a back, the lightbox opens on the side that was clicked and lets the viewer move to the other.
2. It opens whatever was on screen when tapped: the artwork while the panel is closed, the mockup once it is open.

Related: #278 (the image detail page becomes the one buy surface), #284 (the panel's picks live in the URL).

## Decisions

### 1. A new plain viewer; the Studio lightbox is not reused or refactored

Three options were read against the code.

**Reuse `ImageLightbox` as it is.** It is a navigator over a list of images, built for the Studio and the conversation strip. Against this issue:

- It always prints `#N of M` and previous/next arrows. A front/back pair would read "#1 of 2" with arrows, and a single image still shows `#1 of 1`.
- Its image is `max-h-[70vh]` inside `max-w-4xl`, with `rounded-lg`. The issue asks for most of the window.
- It draws an `<img>` on the page background. A mockup needs the multiply blend over `mockupBackdrop(colorHex)`, and the not-yet-loaded state needs the instant layer.
- It has an action row (Order, New design from this, Publish, Delete) that every caller of this issue would have to leave empty, and it imports `GuestPublishPrompt`.
- It has no focus trap and no scroll lock, by its own comments (`image-lightbox.tsx`: "No focus trap — out of scope for this pass"; `studio-client.tsx` relies on that). Requirements here are the opposite.

**Extract a shared shell from `ImageLightbox` and make it use the shell.** Cleaner on paper. Rejected for this issue: it changes the Studio's keyboard, focus and scroll behaviour, which `src/app/design/__tests__/image-lightbox.test.tsx`, `studio-client.test.tsx` and `conversation-images.test.tsx` pin in many places, and the issue is about two other pages. A trap and scroll lock on the Studio lightbox is a reasonable follow-up with its own smoke. It is not part of this PR.

**Write a separate plain viewer (chosen).** About 130 lines, one responsibility, nothing the Studio needs. The cost is a second dialog shell next to `ImageLightbox`, `Modal` and `/preview`'s inline one. That duplication is real, so the viewer is a shell that takes children, not an image component, which keeps it reusable by whoever later converts the others. `/preview` has its own inline lightbox with click-to-zoom (`src/app/preview/page.tsx`, "Fullscreen lightbox with zoom + pan"). It goes away when slice 4 of #278 turns `/preview` into a redirect, so it is not worth extracting from.

### 2. Content is the caller's, so the instant layer and the error overlay come for free

On the image detail page the hero is `SideMockup`: an instant layer (artwork on the shirt colour), the exact Printful mockup crossfaded in once its bytes load, a pending spinner, and an error overlay with Retry. Ruling 2 says "whatever was on screen". If the viewer drew only the mockup, a tap during the render would either do nothing or show a blank panel. So the viewer renders a second `SideMockup` fed by the same `displayFor(side)` and `errorFor(side)` that feed the hero. A mockup that arrives while the viewer is open appears in place. A failed render shows the same message and Retry. Retry re-fires through `retry(side)`, and the viewer stays open.

### 3. Which tap opens, and on which side

- Collapsed (panel closed): the artwork card opens the viewer on the artwork, on the pinned backdrop (`publishedBackdrop(bg)`), using the live `bg` the owner's backdrop picker holds. `PublishedImageView` owns this viewer, because only it knows `bg`.
- Expanded: tapping the hero opens the viewer on the hero's side. With a back picked, the hero is whichever side is prominent, so "the side that was clicked" is the hero's side. The tile keeps its existing job (tapping it swaps which side is large). Nico's ruling does not say a tile tap should open the viewer, and the swap is a shipped feature with tests (#167), so it stays. If Nico wants a tile tap to open the viewer on the tile's side, it is a one-line change to the tile's `onSelect`. Flagged in the PR body.
- Inside the viewer, a Front / Back switch (and Left/Right arrow keys) moves between the two sides. It changes only the viewer's own state. Closing leaves the page's `prominent` side as it was.
- Checkout: a line's front tile opens on the front (cached mockup, else the artwork on the shirt colour, the same fallback the tile uses). The 40px back thumbnail opens on the back. The checkout summary holds no back mockup, only the back artwork URL, so the back face is the artwork on the shirt colour. With both faces the switch appears.

### 4. How it closes

A tap anywhere in the dialog closes it, except on a button or link (the switch, Close, Retry). A phone has almost no backdrop left once the image fills the window, so "tap outside" would be too small a target. A tap on the image closes, which means double-tap zoom is not available on the image; pinch is the zoom gesture (see 6). Escape closes. A visible Close button is 44px.

Escape handling matches `Modal` and `ImageLightbox`: a capture-phase listener on `window` that calls `preventDefault` and `stopPropagation`. `Breadcrumbs` (`src/components/breadcrumbs.tsx`) listens for Escape on `window` and navigates up unless `e.defaultPrevented`. Without `preventDefault`, Escape would close the viewer and also leave the page.

### 5. Dialog mechanics

- **Portal to `document.body`.** A `fixed` element is positioned against the nearest ancestor with a transform, filter or `contain`, and the hero sits inside `overflow-hidden`, `isolate` and `relative` wrappers. A portal removes that dependence. It also sits after the feedback launcher (`fixed bottom-4 right-4 z-50`) in DOM order; the viewer uses `z-[60]` so it does not depend on that order. React synthetic events still bubble through the React tree, so the viewer is rendered as a sibling of the tap target, never inside it (a `SideMockup` select button must not contain it, and its click must not reach the button's handler).
- **Labelled.** `role="dialog"`, `aria-modal="true"`, `aria-label` from the caller.
- **Focus.** On open, Close receives focus. Tab and Shift+Tab wrap inside the dialog. A `focusin` anywhere outside pulls focus back to Close. On close, focus returns to the element that opened it, if it is still in the document. The opener is captured in a layout effect so it runs before the "focus Close" effect (the same ordering trap documented in `image-lightbox.tsx`).
- **No `inert` or `aria-hidden` on the page behind.** Not needed (the portal covers it, and the trap holds focus), and on the checkout page it would touch the ancestor of Stripe's iframe.
- **Scroll lock.** `document.body.style.overflow = "hidden"` on mount; the previous inline value is restored on unmount (including unmount while open). `overscroll-contain` on the dialog. No scrollbar-width compensation (desktop is secondary; the shift is visible only behind the overlay and while it is open).
- **Does not touch history.** No `pushState`, no `replaceState`, no `router` call. Known limit: the Android system Back button leaves the page instead of closing the viewer. Closing it with a history entry would change the stack, and the issue's constraint is that opening and closing leave the URL alone.

### 6. Pinch-zoom is not blocked

Verified: `src/app/layout.tsx` exports no `viewport` and no `maximum-scale` or `user-scalable` anywhere in `src/app`, so the browser default (zoomable) applies. The viewer sets no `touch-action`, calls no `preventDefault` on `touchstart`, `touchmove` or `wheel`, and the dialog is `fixed` with `overflow` clipped on the content box only. Task 2 pins both: a unit test dispatches `touchmove` and `wheel` and expects them not to be default-prevented, and a source test fails if the root layout starts blocking zoom.

### 7. What "larger" can honestly mean

Printful's mockup request here (`createMockupTask` in `src/lib/printful.ts`) sends `format: "jpg"` and no size option, and `renderAndCacheMockup` stores whatever Printful returns in R2 (`designs/{designId}/mockups/…jpg`, `src/lib/mockup-cache.ts`). Nothing in the repo records the pixel size, and Printful's default is not documented in the code, so this plan does not assume it. Task 1 measures one cached mockup and one artwork from a real page and records the numbers in the PR body.

What can be said from the CSS classes already in the code, for a 390 x 844 phone:

- In-page mockup: `SideMockup` hero is `w-full h-72` (288 CSS px tall; 320 at `sm`, 384 at `md`). A square mockup is height-limited to 288px. Portrait 4:5 art is about 230 x 288.
- In the viewer: the content box is about 360 x 770 CSS px. A square mockup is width-limited to about 360px, roughly 1.25x the linear size. A 4:5 mockup is about 360 x 450, roughly 1.55x.
- Collapsed artwork: `max-h-[40vh]` (about 337px) in-page, so a square image gains only about 1.1x.

So on a phone, the layout gain is between about 1.1x and 1.6x, and the rest of the benefit is pinch-zoom. The file is a fixed-size JPEG or PNG: the viewer shows it larger, it does not add detail. Once the image is zoomed past its native pixels the browser upscales it and it looks soft. This plan does not change what Printful renders or how big, and does not promise "full size". A higher-resolution render would be a Printful-side change with cost and cache-key consequences and is a separate issue if Task 1's numbers say the files are small.

On desktop the viewer can take a much bigger step (384px hero to about 800px), which will look soft if the source is about 1000px. The viewer does not cap the displayed size.

### 8. The checkout page: client component for the line, nothing near the form

`ReviewBlock` in `src/app/checkout/page.tsx` is a server-rendered function and has no state. The per-line markup moves, unchanged, into a client component `CheckoutLine` (`src/app/checkout/checkout-line.tsx`) that holds the open state. `EmbeddedCheckoutForm` stays a sibling rendered by the page. Opening the viewer sets state inside `CheckoutLine` only, so the form is not re-rendered, remounted or given a new prop. The overlay is a portal that covers the iframe without touching it, and focus is moved by our code only into the dialog and back to the tile. A test asserts the form's DOM node is the same node and its render count did not change. The nightly Stripe test asserts the iframe element is still connected after an open and close (Task 6), which jsdom cannot see.

### 9. The back-fetch order is unchanged

`BuyHero` fetches the back mockup only after the front has settled. Opening the viewer adds no fetch: `displayFor` and the slots are read, never written, except `loadedMockupUrl` through `onMockupLoad`, which the hero already does. A test asserts `getListingMockup` and `getListingBackMockup` call counts do not change on open or close.

```tsx
// src/components/fullscreen-viewer.tsx
"use client";

import {
  useEffect,
  useLayoutEffect,
  useRef,
  type ReactNode,
} from "react";
import { createPortal } from "react-dom";

export type ViewerOption = { key: string; label: string };

const FOCUSABLE =
  'button:not([disabled]), a[href], [tabindex]:not([tabindex="-1"])';

const LABEL_CLASS =
  "font-mono text-[11px] leading-4 tracking-[0.08em] uppercase";

/**
 * A plain full-window viewer for one image (#285). It is a shell: the caller
 * passes what to enlarge as children, which fill the content box. Used by the
 * image detail page (artwork, and the shirt mockup with its Front/Back
 * switch) and by the checkout page's order summary. The Studio's
 * `ImageLightbox` is a different thing (an image navigator with actions) and
 * is not touched.
 *
 * - Portaled to `document.body`, so no transformed or clipped ancestor can
 *   change what `fixed` is measured against. It renders only after a tap, so
 *   `document` is always there.
 * - Escape closes, with `preventDefault` so `Breadcrumbs`' Escape-to-go-up
 *   skips the keystroke (both listen on `window`).
 * - A tap anywhere closes, except on a button or link (the switch, Close, a
 *   Retry inside the content). Phones leave almost no backdrop.
 * - Focus lands on Close, Tab wraps inside, focus that escapes is pulled
 *   back, and the opener gets focus again on close.
 * - Body scroll is locked while open and the previous inline value restored.
 * - Pinch-zoom is left alone: no `touch-action`, and nothing here calls
 *   `preventDefault` on touch or wheel events.
 * - It never reads or writes the URL or history.
 *
 * The image is shown larger, not sharper: mockups are fixed-size renders from
 * Printful, and zooming past their native pixels is upscaling. Measured sizes
 * (#285, Task 1): <fill in from the PR body, or "not measured">.
 */
export function FullscreenViewer({
  label,
  onClose,
  options,
  activeKey,
  onSelect,
  children,
}: {
  label: string;
  onClose: () => void;
  options?: ViewerOption[];
  activeKey?: string;
  onSelect?: (key: string) => void;
  children: ReactNode;
}) {
  const dialogRef = useRef<HTMLDivElement>(null);
  const closeRef = useRef<HTMLButtonElement>(null);
  const opener = useRef<Element | null>(null);

  // Captured in a LAYOUT effect so it runs before the passive "focus Close"
  // effect below (all layout effects run before any passive effect); a
  // passive capture would record Close itself.
  useLayoutEffect(() => {
    opener.current = document.activeElement;
    return () => {
      const el = opener.current;
      if (el instanceof HTMLElement && document.contains(el)) el.focus();
    };
  }, []);

  useEffect(() => {
    closeRef.current?.focus();
  }, []);

  useEffect(() => {
    const previous = document.body.style.overflow;
    document.body.style.overflow = "hidden";
    return () => {
      document.body.style.overflow = previous;
    };
  }, []);

  useEffect(() => {
    function onKeyDown(e: KeyboardEvent) {
      if (e.key === "Escape") {
        e.preventDefault();
        e.stopPropagation();
        onClose();
        return;
      }
      if (e.key === "Tab") {
        const dialog = dialogRef.current;
        if (!dialog) return;
        const nodes = Array.from(
          dialog.querySelectorAll<HTMLElement>(FOCUSABLE)
        );
        if (nodes.length === 0) return;
        const first = nodes[0];
        const last = nodes[nodes.length - 1];
        const active = document.activeElement;
        if (!dialog.contains(active)) {
          e.preventDefault();
          first.focus();
        } else if (e.shiftKey && active === first) {
          e.preventDefault();
          last.focus();
        } else if (!e.shiftKey && active === last) {
          e.preventDefault();
          first.focus();
        }
        return;
      }
      if (
        options &&
        options.length > 1 &&
        (e.key === "ArrowLeft" || e.key === "ArrowRight")
      ) {
        const i = options.findIndex((o) => o.key === activeKey);
        const j = e.key === "ArrowLeft" ? i - 1 : i + 1;
        if (i >= 0 && j >= 0 && j < options.length) {
          e.preventDefault();
          onSelect?.(options[j].key);
        }
      }
    }
    window.addEventListener("keydown", onKeyDown, true);
    return () => window.removeEventListener("keydown", onKeyDown, true);
  }, [onClose, options, activeKey, onSelect]);

  useEffect(() => {
    function onFocusIn(e: FocusEvent) {
      const target = e.target as Node | null;
      if (target && dialogRef.current && !dialogRef.current.contains(target)) {
        closeRef.current?.focus();
      }
    }
    document.addEventListener("focusin", onFocusIn);
    return () => document.removeEventListener("focusin", onFocusIn);
  }, []);

  const showSwitch = !!options && options.length > 1;

  return createPortal(
    <div
      ref={dialogRef}
      role="dialog"
      aria-modal="true"
      aria-label={label}
      data-testid="fullscreen-viewer"
      className="fixed inset-0 z-[60] flex flex-col overscroll-contain bg-background pt-[env(safe-area-inset-top)] pb-[env(safe-area-inset-bottom)]"
      onClick={(e) => {
        if ((e.target as Element).closest("button, a")) return;
        onClose();
      }}
    >
      <div className="flex items-center justify-between gap-3 p-2">
        {showSwitch ? (
          <div role="group" aria-label="View" className="flex">
            {options!.map((o, i) => {
              const active = o.key === activeKey;
              return (
                <button
                  key={o.key}
                  type="button"
                  aria-pressed={active}
                  data-testid={`fullscreen-viewer-option-${o.key}`}
                  onClick={() => onSelect?.(o.key)}
                  className={`min-h-11 min-w-11 border border-foreground px-4 ${LABEL_CLASS} ${
                    i > 0 ? "-ml-px" : ""
                  } ${
                    active
                      ? "bg-foreground text-background"
                      : "bg-background text-foreground"
                  }`}
                >
                  {o.label}
                </button>
              );
            })}
          </div>
        ) : (
          <span />
        )}
        <button
          ref={closeRef}
          type="button"
          onClick={onClose}
          data-testid="fullscreen-viewer-close"
          className={`min-h-11 min-w-11 border border-foreground bg-background px-4 text-foreground ${LABEL_CLASS}`}
        >
          Close
        </button>
      </div>
      <div
        data-testid="fullscreen-viewer-content"
        className="relative mx-2 mb-2 min-h-0 flex-1 overflow-hidden border border-border"
      >
        {children}
      </div>
    </div>,
    document.body
  );
}
```

```tsx
"use client";

import { useState } from "react";
import { FullscreenViewer } from "@/components/fullscreen-viewer";
import { mockupBackdrop } from "@/lib/instant-preview";
import type { CheckoutLineSummary } from "@/lib/embedded-checkout-session";

type FaceSide = "front" | "back";

/**
 * One line of the checkout order summary (moved out of `ReviewBlock` in
 * page.tsx so it can hold state). Tapping the front tile, or the back
 * thumbnail, opens the viewer (#285) on that face. The viewer is a portal and
 * the open state lives here, so the Stripe form beside the summary is not
 * re-rendered, remounted or covered by anything but the overlay.
 *
 * The face is what the tile already shows: the cached front mockup, else the
 * artwork on the shirt colour. The summary has no back mockup, only the back
 * artwork, so the back face is that artwork on the shirt colour.
 */
export function CheckoutLine({ line }: { line: CheckoutLineSummary }) {
  const [viewing, setViewing] = useState<FaceSide | null>(null);

  const hasFront = Boolean(line.mockupUrl || line.frontImageUrl);
  const hasBack = Boolean(line.backImageUrl);
  const name = line.productName ?? "Shirt";
  const options =
    hasFront && hasBack
      ? [
          { key: "front", label: "Front" },
          { key: "back", label: "Back" },
        ]
      : undefined;

  return (
    <div className="border-t border-border pt-4 space-y-2">
      {/* the tile, product text and back row: the markup ReviewBlock had */}
      {viewing && (
        <FullscreenViewer
          label={`${name}, larger view`}
          onClose={() => setViewing(null)}
          options={options}
          activeKey={viewing}
          onSelect={(key) => setViewing(key === "back" ? "back" : "front")}
        >
          <Face line={line} side={viewing} name={name} />
        </FullscreenViewer>
      )}
    </div>
  );
}

function Face({
  line,
  side,
  name,
}: {
  line: CheckoutLineSummary;
  side: FaceSide;
  name: string;
}) {
  if (side === "front" && line.mockupUrl) {
    return (
      <div
        data-testid="checkout-viewer-face"
        data-side="front"
        className="isolate h-full w-full"
        style={{ backgroundColor: mockupBackdrop(line.colorHex) }}
      >
        {/* eslint-disable-next-line @next/next/no-img-element */}
        <img
          src={line.mockupUrl}
          alt={`${name} in ${line.color}`}
          className="h-full w-full object-contain mix-blend-multiply"
        />
      </div>
    );
  }
  const src = side === "front" ? line.frontImageUrl : line.backImageUrl;
  return (
    <div
      data-testid="checkout-viewer-face"
      data-side={side}
      className="h-full w-full"
      style={{ backgroundColor: line.colorHex }}
    >
      {src && (
        // eslint-disable-next-line @next/next/no-img-element
        <img
          src={src}
          alt={`${side === "front" ? "Front" : "Back"} design on a ${line.color} ${name}`}
          className="h-full w-full object-contain p-[12%]"
        />
      )}
    </div>
  );
}
```
