## Process change from batch 1

Subagents launched with the Agent tool cannot launch agents of their own. In
batch 1 four of five controllers therefore built and self-reviewed alone; the
fifth (C) ran its implementers and reviewers as `claude -p` subprocesses and
got independent reviews that way. For batch 2:

1. Controllers run implementers and task reviewers as `claude -p` subprocesses
   (`--model sonnet` for implementers and task reviews, `--model haiku` for
   one-line re-reviews), restricted to the controller's worktree.
2. The main session runs one independent Opus whole-branch review per branch
   before opening its PR (every batch-1 review found real defects), then a
   fix round and a scoped re-review.
3. Before opening PRs, build the combined tree of all batch branches plus main
   locally and run the gate, as done for batch 1 — it catches semantic
   conflicts `git merge-tree` cannot see.
