## Task 1 — the front mockup must not wait on the back

File: `src/app/preview/page.tsx`

The front's auto-trigger effect currently contains
`if (mockupLoading.back) return;`, and `mockupLoading.back` is in its dep
array. That makes the primary view hostage to the secondary one: with a back
fetch in flight (Printful polling allows up to 55s), changing the front leaves
the hero on its placeholder artwork with a spinner until the back finishes.

Remove that guard and drop `mockupLoading.back` from the effect's dependency
array. Leave the back's own gate (`frontMockupSettled`) exactly as it is —
the back still waits for the front.

Update the comment block above the effect: the paragraph beginning "Also waits
on an in-flight back fetch" is now false and must go. State instead that the
front never waits on the back, because the front is what the buyer looks at.

Test (`src/app/preview/__tests__/preview-sides.test.tsx`): with a back fetch
deferred (unresolved promise), a front change must issue its own mockup fetch
without waiting for the back promise to settle. Assert on the mockup action
being called for the front while the back's promise is still pending.
Mutation-check by restoring the guard — the new test must fail.

Keep the existing front-then-back ordering test passing unchanged.

## Task 2 — two conditional-render gates

Two independent one-line gating fixes. Same shape: an element renders in a
state where it has no meaning.

### 2a — the side label pill

Files: `src/components/side-mockup.tsx`, its test file.

The `Front`/`Back` label pill renders unconditionally. When the page shows
only one side (multi-placement off, or a blank with no back placement), the
hero carries a "Front" badge with no counterpart anywhere on the page — it
labels a distinction the user cannot act on.

Add an optional prop (default preserving today's behaviour for the
two-sided callers) that suppresses the pill, and have the callers pass it so
the pill renders only when the layout actually has two sides. Decide the prop's
name and polarity yourself; state the choice in your report. The pill must
still be readable to assistive tech whenever it renders.

Callers: `src/app/preview/page.tsx` and `src/app/d/[imageId]/buy-hero.tsx`
(two `<SideMockup>` call sites each — a hero and a tile).

Test: the pill is absent for a lone front, present when both sides show.

### 2b — `backOffered` ignores whether the blank has a back

File: `src/app/d/[imageId]/buy-hero.tsx` (around line 260)

`backOffered: !!backEnabled` omits the `productSupportsPlacement(product,
"back")` check that `/preview` applies. Inert today (all three active blanks
have a back placement), latent if a back-less blank is ever activated: the
add-back tile would appear, the mockup render would throw inside
`getPlacement`, and a purchase could carry an unprintable back pin.

Mirror `/preview`'s condition — read how `/preview` composes it and use the
same helper. Test that a blank without a back placement offers no back.

## Task 3 — order lines paired to identities by a mutable cursor

File: `src/lib/user-orders.ts` (around line 84)

Lines are re-paired to their resolved identities with a `let cursor = 0`
incremented inside a nested `.map`. It is correct only because `allLines` was
built by the same `flatMap` and `Array.prototype.map` runs in order. Any later
reorder, filter, or async-ification silently attaches the wrong thumbnail AND
the wrong "Designed by" to an order line — money-adjacent display.

Replace the mutable cursor with an explicit per-order offset computed
alongside `allLines`, so each order slices the identity array at a position it
carries rather than one accumulated by side effect. Pure refactor: no
behavioural change.

The two existing real-DB suites over this function must pass unmodified — do
not loosen an assertion. Add a test that pins the pairing: an order with
multiple lines whose identities differ must map each line to its own
identity, and it must still hold when a preceding order contributes zero
lines.
