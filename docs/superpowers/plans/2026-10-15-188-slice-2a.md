# #188 Slice 2a: Reference-Image Attach in the Studio Composer

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Studio composer gets an "Attach image" control. A phone user picks one image from their library, it lands in the Studio as a result, and the composer is anchored to it so the next line they type is an edit of it. This is the capability of `/design`'s upload that the thread's retirement would otherwise remove (spec ruling 4, `docs/superpowers/specs/2026-10-15-188-slice-2-retire-design-thread.md`).

**Architecture:** A new Studio server action `attachReferenceImage` (`src/app/studio/actions.ts`) gates on `requireStudioActionSession`, spends a new per-day upload quota, then calls the existing `uploadReferenceImage` (`src/app/design/actions.ts:1116`), which already stores the object, inserts an `image` row (`operation=upload`, linked as an `output` of the conversation by `insertDesignImage`, `src/lib/design-images.ts:289`), writes a chat turn and bumps `design.updated_at`. A pure helper `src/lib/reference-image.ts` validates and normalizes the bytes (size cap, decodable, EXIF rotation applied, longest side 2048, PNG) and `uploadReferenceImage` calls it, so `/design` gets the same hardening until it is deleted. In `StudioClient` the Composer gets the control; on the bench an attach starts a new conversation (client-minted design id, like a Generate) and sets the bench anchor to the upload; on the focused stage it adds the upload to the shown conversation and moves the stage to it.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4 (Paper tokens), Drizzle + libSQL (in-memory for tests), `sharp` (already a dependency, `src/lib/image-luminance.ts:36`), Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-15-188-slice-2-retire-design-thread.md` (gap 3 in section (b), ruling 4, order-of-work item 0).

## Rulings made in this plan (Claude's; Nico can reverse each, cost noted)

- R1. **Bench attach starts a new conversation; stage attach joins the shown one.** On the bench with no anchor the upload gets a client-minted design id, so it becomes its own lane (same as a first Generate). With a bench anchor (the restore after a refused submit, `giveBack`) the upload joins the anchor's conversation. On the stage it joins the focused conversation. Cost if wrong: a user who wanted a reference image inside the lane they were editing, from the bench, has to open the stage first. The edit lines they type are anchored to the upload either way.
- R2. **Limits:** 3 MB per file checked on the device before reading it, and the same 3 MB check on the decoded bytes on the server, longest side resized down to 2048 px, always stored as PNG. Vercel Functions cap a request body at 4.5 MB regardless of `serverActions.bodySizeLimit` (10mb in `next.config.ts`; the platform rejects the request before Next sees it), and base64 adds a third, so 3 MB raw becomes about 4 MB on the wire, under 4.5 MB. Cost if wrong: a 3.5 MB camera original is refused where it might have worked; a device-side canvas downscale before upload, which would let larger camera originals through, is a follow-up (not in this slice).
- R3. **Upload quota:** a new per-day count, never refunded, `upload:user:<id>` cap 40 and `upload:ip:<ip>` cap 100 (`USER_UPLOAD_DAILY_CAP`, `USER_IP_UPLOAD_DAILY_CAP`, overridable like the checkout caps). No upload quota exists today, so each attach writes an object to R2 for any guest. The numbers are well above what one person attaches in a day and exist to bound storage abuse. Cost if wrong: a shared network (100 a day per IP) could be refused; the override handles it.
- R4. **Stage attach follows the upload.** After a successful attach on the stage the stage moves to the new result (`go({ designId, imageId }, "push")`), so the anchor chip shows the uploaded image. Cost if wrong: a user adding several references in a row has to tap back to the earlier result. One reference per attach is the expected case.
- R5. **No change to the upload's chat turn or the lane title.** The lane title is the first user turn (`src/lib/studio.ts:314-337`), so an upload-only lane stays titled "Uploaded reference image: cat.png" even after later Generates. Cost if wrong: a clumsy lane title; changing it means touching the turn `/design` also stores and the title rule, a separate decision.
- R6. **A refused or failed attach never clears the draft text** in the composer and never changes the anchor.
