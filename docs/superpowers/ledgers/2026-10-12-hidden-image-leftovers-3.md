## Rulings

- R1: `/checkout` returns `expired` for a hidden line and does not expire the Stripe session or touch the order row — the ruling on #310 is "stop the buyer at /checkout"; expiring sessions was described and not ruled — if wrong: a buyer with the form already open can still pay for up to two hours (the gap Nico was told about).
- R2: `deleteDesignImage` refuses every admin-hidden id, including one that would only be detached (a seed link) — the ruling says "a hidden refusal in deleteDesignImage" and no UI path sends a hidden id since #309; one rule is simpler to reason about than a per-outcome rule — if wrong: an owner cannot detach a hidden seed from a thread by a direct call, and deletes the lane instead.
- R3: the thumbnail rule checks only lines already marked unavailable — a hidden pin always fails `cartLineStillValid` — if wrong (some path lets a hidden pin read as available): that line would show its thumbnail and also check out, which is a larger bug than the thumbnail.
- R4: #321 is built in this batch although the ruling's words are "open a follow-up" — Nico approved the batch list that named it on 2026-10-12 — if wrong: one small PR to close unmerged.
- R5: `canStartFromImage` itself refuses a hidden image for the owner (rather than a second check in the action) — the action already selects `isHidden` and the function is the one rule — if wrong: another caller of `canStartFromImage` changes behaviour; the implementer lists the callers.
- R6: slices run without per-task Sonnet reviews; each branch gets the controller's gate and an Opus whole-branch review (CLAUDE.md, batch lesson of 2026-10-01 for small slices) — if wrong: a task-level defect is found one step later, by the whole-branch review.
