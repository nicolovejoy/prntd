## Preflight rulings

1. **Items 1 and 3 together, one PR.** They share the page and its test file, and item 1's screen only makes sense once item 3 bounds who sees the page. Cost if wrong: a review that has to hold two concerns at once.
2. **The order read moves to `src/lib/order-receipt.ts` and `actions.ts` is deleted** rather than adding a session read inside the action. A `"use server"` export is an endpoint anyone can call with a session id; a lib function is not, and the page is its only caller. Cost if wrong: the page directory has no `actions.ts` (the convention says each page directory has one; `/orders` already reads through `src/lib/user-orders.ts` the same way).
3. **Signed-out or anonymous → sign-in with `next` = this page's path and query (`session_id` and `from` only); a signed-in non-owner → "Order not found."** The first keeps a buyer whose cookie was lost on the way back from Stripe; the second gives a stranger holding a session id nothing, and does not say whether the order exists. Cost if wrong: a stranger learns nothing either way; a buyer with a lost cookie signs in and returns.
4. **The "checking" state covers a failed or timed-out Stripe read and an unrecognised session status**, not only the failed read. We do not know the state in either case. Cost if wrong: a pending order with a session status Stripe adds later shows the checking screen instead of the receipt until the webhook runs, which is the fail-closed side.
5. **Wording (Nico left it to Claude):** heading "Checking your payment.", body "We couldn't confirm it just now. Reload in a moment. A paid order appears under Orders once it's confirmed.", button "Reload". Neutral, no "nothing was charged" (not known), no "went through" (not known). Cost if wrong: a copy edit.
6. **Reload is a plain anchor to the page's own URL**, not a `Link`, so the server read runs again. Cost if wrong: none; a full navigation is the safe form.
7. **The `loadFailed` screen is left as is.** It shows no order data, and its "Your payment went through." line predates this slice; changing it is a separate copy decision. Recorded as a known limit.
8. **`src/proxy.ts` unchanged.** `/order` stays a funnel route; the page's check is the gate, which also covers a visitor who has a cookie but no real account.
