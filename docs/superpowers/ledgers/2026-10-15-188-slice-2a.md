# Ledger: #188 slice 2a (Studio attach image), 2026-10-15

Plan: `docs/superpowers/plans/2026-10-15-188-slice-2a.md`. Rulings R1 to R6 stand except R2.

## Rulings and departures

1. **R2 corrected (first commit).** Vercel Functions cap a request body at 4.5 MB whatever `serverActions.bodySizeLimit` says (10mb in `next.config.ts`; the platform rejects first). Base64 adds a third, so the cap is 3 MB per file (about 4 MB on the wire). Every "6 MB" in the plan became "3 MB", including the copy string and the smoke. The 2048 px server resize stays. The device-side downscale shipped in this slice after review (fix round, item 16 below).
2. **Limits live in `src/lib/reference-image-limits.ts`**, not in `reference-image.ts`. The plan allowed this fallback; I did it up front because `reference-image.ts` has a dynamic `import("sharp")` that a client bundle would try to resolve. The limits file holds the byte and side caps, the accepted MIME list (`REFERENCE_IMAGE_TYPES`) and the two reason strings (`too_large`, `unsupported`). `reference-image.ts` re-exports them, so tests and the server import either.
3. **Empty buffer** is checked before the sharp call (`unsupported`), after the size check.
4. **GIF pinned:** sharp with `animated: false` accepts a GIF and keeps the first frame; the file input's `accept` and the device check still exclude GIF, so only a direct action call reaches it.
5. **Existing fixtures fixed, not the helper:** `image-provenance` and `conversation-close` integration tests uploaded non-image bytes ("png", "x"); they now upload a 1x1 PNG, since uploads are decoded before any other step. In `conversation-close` the closed refusal therefore still fires after the decode (the helper runs before `getOrCreateDesign`, as the plan orders it).
6. **`attachReferenceImage` ownership check** is its own query on `design` by id (unscoped). `findOwnedDesign` already throws `Unauthorized` for a foreign id; the separate check stays because it runs before the quota is spent (so a foreign id or a closed conversation costs no unit). A closed one returns `refused` before quota. Quota is spent before any decode, so an oversize or undecodable file still costs one unit (never refunded, per R3).
7. **Design id is not validated as a UUID** in the action, matching `generateDesign`.
8. **`pollOnce` now returns the fetched lanes (or null)** instead of void. Existing callers ignore or `Promise.resolve` it. `attach` needs the lanes it fetched: `pollOnce` returns null when a poll is already running, so `attach` awaits `pollInFlight` and polls again (that poll may predate the upload).
9. **Anchor title:** the bench anchor set after an attach carries the lane's title ("Uploaded reference image: cat.png") instead of the plan's `null` (which would render "Editing · Untitled").
10. **Where the result lands depends on where the user is when it arrives.** Started on the stage: the stage moves to the upload only if it still shows that conversation. Started on the bench: the anchor is set only if the user is still on the bench. Otherwise the upload just exists as a cell. This avoids writing a hidden bench anchor from the stage (the same concern `giveBack` documents).
11. **If the refetch does not list the upload** (read failed), no anchor is set and no notice is shown; the lane appears on the next refetch. Setting the anchor would be cleared by the next lanes change.
12. **Device checks** run in this order: type (PNG, JPEG, WebP), then size. Both show their line without calling the action.
13. **Layout:** the hint line is its own full-width line; the row below holds Attach (left) and Generate (right). The Attach notice is a `role="status"` paragraph beside the existing notice line.
14. **`server-action-exports`:** `src/app/studio/actions.ts` also exports the type `AttachReferenceImageResult` (erased at build).

## Not done / follow-ups

15. **Two existing integration tests got an `@/lib/ai` mock** (`delete-conversations`, `studio-actions`): importing `studio/actions` now loads `design/actions`, whose `ai.ts` builds the Anthropic client at module scope and throws under jsdom. ## Fix round (Opus whole-branch review, READY WITH FIXES)

16. **Pixel limit (item 1).** sharp is built with `{ animated: false, limitInputPixels: 40_000_000 }`; a small file declaring a huge raster (an 8000x8000 PNG in the test) is refused as `unsupported`, a 12 MP JPEG passes.
17. **Shared body (item 2).** The upload body moved to `src/lib/store-reference-image.ts` (`storeReferenceImage`, a result union `ok | too_large | unsupported | closed`; Unauthorized and unexpected failures throw). Order: normalize, find or create the design, R2, rows. `uploadReferenceImage` and `attachReferenceImage` both call `consumeUploadQuota` first, so a direct call to the public design action is capped like the Studio's. `studio/actions.ts` no longer imports `design/actions.ts`; the two `@/lib/ai` test mocks were reverted. Judgment call: for the design action the quota is spent before the closed check (the Studio action checks closed first). If a step after a design insert fails, the design this call created is deleted best-effort, so no empty lane remains; an existing conversation is never touched. The `getOrCreateDesign` docblock no longer calls an empty design harmless (it still can happen for `sendChatMessage`).
18. **Device downscale (item 3).** `src/lib/client-image-downscale.ts`: `createImageBitmap` (orientation from the image) + canvas; if the file is over 3 MB or its longest side is over 2048 px it is redrawn at 2048 px and exported as JPEG at 0.9, flattened onto white for JPEG and WebP sources; a PNG source stays PNG (no fill, no quality argument, named `.png`) so transparency survives, which is the chosen behaviour (final fix); a file with neither condition, and any environment without the APIs, or any failure, returns the original. The handler runs the type check, then the downscale, then the 3 MB cap on the result, and uploads the result (its name ends `.jpg` when downscaled). The busy state covers the downscale. Cost if wrong: a large downscaled PNG may stay over 3 MB and be refused; JPEG artifacts on photos at 0.9.
19. **Server format check (item 4).** `metadata().format` must be png, jpeg, webp or gif; SVG and TIFF are `unsupported`.
20. **Second bench attach (item 5), ruling.** While the bench anchor points at the first upload, a second attach joins the anchored lane (the anchor is the conversation being worked in). Pinned by a test. Cost if wrong: two unrelated references end up in one lane; clearing the anchor first starts a new one.
21. **Closed race (item 7).** The shared body's `closed` reason maps to `ATTACH_CONVERSATION_CLOSED` in the Studio action and to the closed message in the design action.
22. **Accessibility (item 8).** The `role="status"` paragraph is always mounted (empty, `empty:hidden`). The Attach button uses `aria-disabled` with an ignored click while uploading, so keyboard focus stays on it.
23. **Style (item 9).** The disabled look follows the `Button` convention (dotted border, muted text) through `aria-disabled:` variants; the input's `accept` is built from `REFERENCE_IMAGE_TYPES`.
24. **File name cap (item 11).** `fileName` is cut to 120 characters in the shared body (prompt, chat turn, lane title).
25. **Known, not changed (finding 10).** A refetch that misses the upload shows nothing; the lane appears on the next poll or reconcile.
