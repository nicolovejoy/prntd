# Ledger: #188 slice 2a (Studio attach image), 2026-10-15

Plan: `docs/superpowers/plans/2026-10-15-188-slice-2a.md`. Rulings R1 to R6 stand except R2.

## Rulings and departures

1. **R2 corrected (first commit).** Vercel Functions cap a request body at 4.5 MB whatever `serverActions.bodySizeLimit` says (10mb in `next.config.ts`; the platform rejects first). Base64 adds a third, so the cap is 3 MB per file (about 4 MB on the wire). Every "6 MB" in the plan became "3 MB", including the copy string and the smoke. The 2048 px server resize stays. A device-side canvas downscale, which would let larger camera originals through, is a follow-up.
2. **Limits live in `src/lib/reference-image-limits.ts`**, not in `reference-image.ts`. The plan allowed this fallback; I did it up front because `reference-image.ts` has a dynamic `import("sharp")` that a client bundle would try to resolve. The limits file holds the byte and side caps, the accepted MIME list (`REFERENCE_IMAGE_TYPES`) and the two reason strings (`too_large`, `unsupported`). `reference-image.ts` re-exports them, so tests and the server import either.
3. **Empty buffer** is checked before the sharp call (`unsupported`), after the size check.
4. **GIF pinned:** sharp with `animated: false` accepts a GIF and keeps the first frame; the file input's `accept` and the device check still exclude GIF, so only a direct action call reaches it.
5. **Existing fixtures fixed, not the helper:** `image-provenance` and `conversation-close` integration tests uploaded non-image bytes ("png", "x"); they now upload a 1x1 PNG, since uploads are decoded before any other step. In `conversation-close` the closed refusal therefore still fires after the decode (the helper runs before `getOrCreateDesign`, as the plan orders it).
6. **`attachReferenceImage` ownership check** is its own query on `design` by id (unscoped), because `uploadReferenceImage`'s `getOrCreateDesign` would try to insert another user's id and fail on the primary key. A foreign id throws `Unauthorized`; a closed one returns `refused` before quota. Quota is spent before any decode, so an oversize or undecodable file still costs one unit (never refunded, per R3).
7. **Design id is not validated as a UUID** in the action, matching `generateDesign`.
8. **`pollOnce` now returns the fetched lanes (or null)** instead of void. Existing callers ignore or `Promise.resolve` it. `attach` needs the lanes it fetched: `pollOnce` returns null when a poll is already running, so `attach` awaits `pollInFlight` and polls again (that poll may predate the upload).
9. **Anchor title:** the bench anchor set after an attach carries the lane's title ("Uploaded reference image: cat.png") instead of the plan's `null` (which would render "Editing · Untitled").
10. **Where the result lands depends on where the user is when it arrives.** Started on the stage: the stage moves to the upload only if it still shows that conversation. Started on the bench: the anchor is set only if the user is still on the bench. Otherwise the upload just exists as a cell. This avoids writing a hidden bench anchor from the stage (the same concern `giveBack` documents).
11. **If the refetch does not list the upload** (read failed), no anchor is set and no notice is shown; the lane appears on the next refetch. Setting the anchor would be cleared by the next lanes change.
12. **Device checks** run in this order: type (PNG, JPEG, WebP), then size. Both show their line without calling the action.
13. **Layout:** the hint line is its own full-width line; the row below holds Attach (left) and Generate (right). The Attach notice is a `role="status"` paragraph beside the existing notice line.
14. **`server-action-exports`:** `src/app/studio/actions.ts` also exports the type `AttachReferenceImageResult` (erased at build).
