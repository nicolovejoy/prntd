## Preflight rulings

1. **The rule the #314 adversarial review named, as written:** Production accepts the app origin only; a Preview compares the Origin header against `VERCEL_URL` and `VERCEL_BRANCH_URL`. The regular expression of the host shape goes. Cost if wrong: a Preview request on a host Vercel names some other way returns the buyer to Production's `/order/confirm`, where the order does not exist (the state the regular expression was added to avoid). This project has no Preview alias, and Nico's Preview smokes open the Vercel bot's link, which is one of the two.
2. **`*.prntd.org` is no longer trusted.** Only `prntd.org` serves the app and it is the app origin, so the exact comparison covers it. Cost if wrong: a buyer on an unexpected `prntd.org` subdomain gets a `return_url` on `prntd.org`; the order still confirms there (the page reads by session id).
3. **Production never trusts its own `VERCEL_URL`.** A Production buyer is on `prntd.org`; a session returning to a `vercel.app` host lands with no session cookie. Cost if wrong: none found; no Production request arrives on that host.
4. **Host match is case-insensitive and compares `origin.host` (with port) to the env value.** Vercel's values carry no port. Cost if wrong: an origin with an explicit non-default port falls back to the app origin.
5. **The env values travel as a plain object parameter** (`VercelDeployment`, filled by `vercelDeployment()`), so the function stays pure and the three callers change by one argument. Cost if wrong: one more import at three call sites.
