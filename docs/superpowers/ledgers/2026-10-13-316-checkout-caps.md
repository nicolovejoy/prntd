## Preflight rulings (the three questions on #316)

1. **Question 1, cap checkout attempts per account per day: yes.** `USER_CHECKOUT_DAILY_CAP` 30 per signed-in account, `USER_IP_CHECKOUT_DAILY_CAP` 100 per IP, both UTC-day buckets through the existing `consumeBuckets`, both env-overridable with the same `parseDailyCap` pattern as the generation and chat caps. No guest cap: guests never reach either action. Never refunded. Cost if wrong: a buyer who clicks Checkout more than 30 times in a day is refused until the UTC day turns; the fix is an env change, no deploy of code.
2. **Question 2, cap the lines in a cart: yes.** `CART_MAX_LINES` 40, enforced by `addToCart` before its insert and re-checked by `checkoutCart`. Soft at the boundary (two adds landing together at 39 can both succeed; checkout then refuses until one is removed). Stripe takes up to 100 line items per session, so 40 keeps every cart under it. Cost if wrong: a one-constant change; nobody has a 40-line cart today.
3. **Question 3, the refusal lines: Claude's copy, in the style of the existing refusals.** "You've reached today's checkout limit. Try again later." / "This network has hit today's checkout limit. Try again later." (mirroring the generation limit lines), "Your cart is full. Remove a line to add another." and "Your cart has too many lines to check out. Remove some to continue." (mirroring `CART_LINE_UNAVAILABLE`). All four in `src/lib/action-copy.ts`, returned as data so Production's masking of thrown server-action errors does not hide them. Cost if wrong: four string edits.
4. **Where the attempt is counted:** right after the sign-in check, before `buildCart` (which runs a Printful quote) and before any write, in both actions. A click refused for a stale line or an empty cart still spends an attempt. Cost if wrong: a buyer with a stale cart line spends attempts on refused clicks; thirty is still far from a real buyer's day. The adversarial review is asked to weigh this.
5. **`createCheckoutSession` (`src/app/order/actions.ts`, the `/preview` path) is not counted.** No UI reaches it since one-buy-surface slice 4 and slice 6a removes it; a comment at its sign-in check says so. Cost if wrong: a direct caller of a dead action is uncapped until 6a.
6. **`clientIp` moves to `src/lib/client-ip.ts`** so three actions share it. Cost if wrong: none; a one-function move.
7. **Stacked on #317's branch** instead of waiting for it to merge, so the two slices run in parallel today. Cost if wrong: a rebase with a conflict in `src/app/cart/actions.ts` if #317's review changes that file again.
