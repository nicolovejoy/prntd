## Rulings

- Ruling: R1. #315's proposal is built as written in the issue (it is headed "Proposal to discuss"); Nico's "yes" was to expiring on a hidden refusal "with #315". Why: his answer named #315 and the two share one helper. Cost if wrong: one PR to shrink to the hidden-refusal half (E3 plus E1's single-session function).
- Ruling: R2. One live checkout per buyer across both surfaces: a cart checkout expires an earlier image-detail-page session and the reverse. Why: #315's wording is "that buyer's other open sessions". Cost if wrong: a buyer with two checkouts open in two tabs on purpose finds the older form expired (nothing charged).
- Ruling: R3. On a confirmed expiry the order is marked abandoned at once through `handleStripeCheckoutExpired`, not left to the webhook. Why: Preview has no webhook, so its pending orders would be retried by every later checkout; the writer is conditional and the webhook delivery then finds nothing to do. Cost if wrong: none found; an order is abandoned a few seconds earlier than the webhook would have done it.
- Ruling: R4. The expiry is awaited, bounded by the 3 s Stripe timeout, at most ten sessions, only orders younger than the session lifetime plus five minutes. Why: the attempt must be made before the buyer reaches the new form; `after()` would make it unobservable and untestable in the lib. Cost if wrong: a checkout click is up to 3 s slower when Stripe is slow and an earlier session is open.
- Ruling: R5. If the `expire` call fails, nothing else stops the earlier session (the loader does not refuse a superseded order from the database). Why: #315 lists that as an alternative, not as part of the proposal. Cost if wrong: after a Stripe error at that moment the earlier session stays payable for up to two hours, as today.
- Ruling: R6. The feed's rule is "what the buy gate would sell to a signed-out visitor", so an image with no conversation id at all also leaves the Shop. Why: the page shows no Order for it either. Cost if wrong: a legacy listing with no conversation id disappears from the Shop; the parity read lists every listing left out, and Nico runs it on Production before the merge.
- Ruling: R7. The parity script's exit code does not change for a listing left out for lack of a conversation. Why: it is the ruled behaviour, not a disagreement. Cost if wrong: none.
- Ruling: R8. Merges of #323 and #322 handed to Nico: the permission classifier refused `gh pr merge --admin` and refused merging main into #322's branch from this session. Cost: one round trip.
