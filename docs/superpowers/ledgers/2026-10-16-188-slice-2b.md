## Rulings (Claude's; each with its cost if wrong)

- **R1. The seed URL carries its own ids and is never stripped.** The address is `/studio?prompt=&lane=&seed=`. Firing again with the same ids hits `generateDesign`'s replay check (#245), which returns the original job.
  - **Changed in the fix round:** the fired marks are one capped `localStorage` list, `studio-seeds-fired` (the 50 newest seed job ids), so a new tab in the same browser does not fire. The review measured that a `sessionStorage` mark let a new tab re-render a seed whose conversation had been deleted, which spends quota.
  - **Cost if wrong:** while the visitor stays on the bench, the address bar shows the prompt. Removing it needs a #311-safe write.
- **R2. A visitor with a session is redirected on the server; only a sessionless one gets the thin client page.**
- **R3. Missing or malformed ids:** `/studio` redirects to the same idea with fresh ids. That covers old links, a hand-typed `?prompt=` and a sign-in bounce.
- **R4. A stage address wins over a seed.** Since the fix round the check reads the URL itself, not the `initialFocus` prop: Back from the image detail page remounts the Studio from the bfcache with stale props.
- **R5. At the in-flight cap, the seed is not fired.** Its words go into the composer.
  - **Known:** the mark is written first, so a reload leaves the box empty. The URL still holds the idea.
- **R6. `/studio` gets `maxDuration = 300`, the same as `/design`.** The landing visitor's first generation now runs from the Studio.
- **R7. `design-client.tsx`'s own seed effect is now unreachable.** It is left for 2c to delete, with a comment saying so.

## Review findings and outcomes

### Opus whole-branch review at `abfc579`

1. **Important: a rate-limited guest mint sent the visitor to sign-in.**
   - **Cause:** Better-Auth limits `/sign-in*` to 3 per 10 s per IP. `ensureGuestSession` ignored the `{ error }` that `signIn.anonymous()` returns, so the 429 resolved, and the proxy then bounced the visitor to sign-in.
   - **Evidence:** 4 of 12 visitors from one IP. It is also why `guest-funnel.spec.ts:22` passed only on its third attempt.
   - **Fixed:**
     - `ensureGuestSession` rejects with a `GuestSessionError` carrying the status and Retry-After (read through `fetchOptions.onError`, `src/lib/guest-session-error.ts`). The lookup-error path still resolves.
     - `DesignEntry` keeps the status line up, waits Retry-After plus 0.5 s (10 s without it, 15 s at most) and retries once. A second failure shows the failure line and Try again.
     - Caller audit: the awaited calls in `design-client.tsx`, `start-from-image.tsx` and the buy panel's Add to cart are each inside a try/catch that shows the same generic line a server error did. `design-client.tsx`'s fire-and-forget mount call got a log-only `.catch`.
     - e2e: the `/studio` expectations after a fresh mint wait 20 s, and `waitForSessionCookie` waits 20 s. A new mobile-only spec fills the limiter window and checks the retry lands on `/studio`.
2. **Important: the seed URL stayed live in a new tab.** Fixed by R1's `localStorage` list.
3. **Minor: the seed guard read the prop.** Fixed by R4's URL check.
4. **Minor: "no server action runs here" was false.** The site header's `getHeaderState` posts on that page; it is the shape of the 2026-09-08 sign-in hang. Fixed: `DesignEntry` leaves with `window.location.replace`, the sign-in page's precedent. The test-side consequence is a new `mintGuestSession(page)` e2e helper, because a document-navigation hop interrupted specs that ran `goto` again as soon as the cookie appeared.
5. **Minor: at the cap the mark is written first.** Accepted (R5).
6. **Minor: stale docstrings in `maker-hero.tsx` and `design-examples.ts`.** Fixed.
